# 포트폴리오: Jetson Xavier NX에서의 PatchCore 최적화

## 프로젝트 요약

RK3588 NPU에서 최적화한 이상 탐지 모델 PatchCore를 Jetson Xavier NX의 TensorRT로 옮기고, GPU와 DLA의 특성에 맞게 최적화 방법과 측정 방법을 새로 설계한 프로젝트임. 임베디드 검사 시스템에서 같은 모델을 서로 다른 가속기에 맞추는 과정을 다룸.

| 항목 | 내용 |
|:---:|:---:|
| 기간 | 2026년 10월 말에서 11월 초, 진행 중 |
| 대상 | MVTec AD 15개 카테고리, 입력 256 |
| 하드웨어 | Jetson Xavier NX 8GB(GPU, DLA 2개), RTX 3060 Ti PC |
| 기술 | PyTorch, ONNX, onnxruntime, TensorRT, CUDA 런타임(ctypes), PowerShell, shell |
| 선행 연구 | patchcore-rk3588-npu(RK3588 NPU에서 977 ms를 5 ms로 단축) |

## 문제

- NPU용 설계는 NPU의 제약(INT8만 지원, 일부 연산이 CPU로 이동, 코어 3개)에 맞춘 타협이었음. 그대로 옮기면 Jetson에서 최적도 공정한 비교도 아님.
- 임베디드 보드는 커널 설정, 펌웨어, 열 관리에 따라 측정값이 크게 달라져 측정 절차도 새로 정해야 했음.

## 접근

- PC의 fp32 onnxruntime 결과를 기준으로 삼고 모든 TensorRT 출력을 같은 채점 코드로 비교함.
- 보드에는 추가 패키지를 설치하지 않고 ctypes로 CUDA 런타임을 불러 TensorRT 실행기를 직접 만듦.
- 정밀도, 구성(차원과 coreset), 연산 장치 배치, 그래프 수준 변환을 각각 독립된 실험 축으로 두고 정확도와 속도를 함께 기록함.
- 속도 외에 전력(장당 에너지), 클럭 상태, 온도를 같이 기록하는 측정 스위트를 만듦.

## 성과

- 혼합 정밀도: 민감한 앞쪽 층만 fp16으로 남기고 나머지를 int8로 만들어, fp32와 같은 정확도(bottle pixel AUROC 0.9849, AUPRO 0.9430)에서 fp16보다 처리량이 60% 이상 높은 엔진을 얻음(최고 성능 모드 189 FPS 대 116 FPS).
- 15개 카테고리 전체 검증: 평균 image AUROC 0.9802, pixel AUROC 0.9784, AUPRO 0.9218로 fp32 기준(0.9816, 0.9780, 0.9215)과 같음.
- 장당 에너지: 최고 성능 모드에서 fp16 130 mJ, 혼합 정밀도 80 mJ임.
- 연산 장치 조합: DLA 코어 2개와 GPU를 동시에 써서 GPU 단독 대비 처리량을 37~41% 늘림. 정확도 검증은 남은 과제임.
- 열 안정성: 10분 연속 실행에서 GPU 클럭 1109 MHz 유지, 온도 69.5°C에서 안정.
- baseline: anomalib 기본 설정 모델이 TensorRT fp16에서 64 ms로 RK3588의 977 ms보다 빠름.
- 구성 재탐색: screw에서 coreset을 1%에서 5%로 올려 AUPRO를 0.9127에서 0.9409로 개선함. NPU 제약에서 고른 값이 GPU에서는 최적이 아님을 확인함.
- 15개 카테고리의 데이터, ONNX, fp32 기준 정확도(평균 image 0.9816, pixel 0.9780, AUPRO 0.9215)를 재현 가능한 스크립트로 정리함.
- 그래프 수준 변환: 후처리와 원본 해상도 리사이즈를 ONNX 그래프 안으로 옮겨도 정확도가 유지됨을 onnxruntime으로 검증함.

## 문제 해결 사례

- 엔트로피 보정 int8의 정확도 붕괴: head의 큰 값 차이가 원인이라는 가설을 세웠으나 층별 고정 실험으로 기각하고, 앞쪽 backbone의 보정 범위 절단이 원인임을 찾음.
- TensorRT 8.2.1의 `TopK(largest=0)` 오류: image AUROC가 0.63으로 나오는 증상에서 head 단독 엔진으로 연산별 출력을 비교해 원인 연산을 좁혔고, 부호 반전으로 대체해 1.0000을 회복함.
- 팬 제어: 회전수 센서가 꺼져 있어 고장으로 오판했으나 `temp_control`이 수동으로 바뀐 것이 원인임을 확인하고, 온도에 따라 PWM을 쓰는 제어 스크립트로 해결함. 잘못된 판단은 기록에서 정정함.
- 온도 센서 누락: JetPack 5.1.4 첫 부팅에서 CPU와 GPU 온도 존이 없는 문제를 부팅 로그와 부트로더 버전(35.1 대 35.6) 불일치로 좁히고, 재부팅 한 번으로 해결함. 문제가 있는 동안에는 전력을 열의 대용 지표로 쓰는 팬 제어로 안전을 확보함.
- QSPI 펌웨어 갱신: 쓰기 전 기존 펌웨어 백업, SSH가 끊겨도 이어지는 분리 실행, 쓴 뒤 전체 읽기 해시 비교로 실패 시 복구 가능한 절차를 만듦.

## 한계와 다음 단계

- DLA 엔진의 정확도 검증, 후처리와 리사이즈를 엔진 안으로 옮긴 그래프의 TensorRT 속도 측정, 연산 장치별 단계 분할 파이프라인이 남은 과제임.
- 전처리와 후처리를 포함한 끝단 처리량은 아직 측정하지 않았음.
- 이 프로젝트 이후에는 같은 보드 계열에서 LLM 추론으로 범위를 넓힐 계획임.
